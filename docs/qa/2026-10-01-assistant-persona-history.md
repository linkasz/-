# 助理人格、对话管理与浮窗控制（2026-10-01）

## 最终范围

- 自然回复与人格设置：自然亲切、简洁直接、耐心伙伴；自定义名称和描述。
- 对话列表：新建、搜索、重命名、删除、打开继续聊；单条消息编辑、删除。
- 用户最新要求覆盖无极调节：浮窗底部短条点击展开全屏，全屏底部白色短条点击收起；两种状态右上角均不显示窗口按钮。底部预留 48dp 点击区域，随键盘和导航安全区抬升，不覆盖输入框。
- 回复浮窗上方声波/状态不再包含麦克风。唯一语音入口在输入区；输入文字时仍可操作语音，发送是独立按钮。
- 不改包名、版本、签名、Room 45，不安装、不推送、不发布。

## 诊断证据

### 回复机械

`DayAgentService.chat` 原独立天气问句直接返回 `QuickWeather` 的机器字段摘要，没有进入配置好的模型。因此单改 system prompt 无法改善截图中的回答。

本轮查询一次后把成功预报提供给当前文字助理，并加入人格与自然表达指令；已有天气事实时，后续工具列表不再提供 WEATHER_QUICK。模型失败时用真实结构化预报生成自然短句，不让查询成功的结果被搁置。自然短句保留准确温度，不杜撰风向或城市名称。语音继续采用转写→现有文字助理→可选朗读的共同链路。

### 拖动

用户视频时长 8.8 秒，592×1280、30 fps。本轮读取视频并以每 0.5 秒一帧查看接触表；约 2～7 秒内，面板高度与输入栏位置出现跳变。原 handle 每个 pointer delta 使用上一轮重组后的高度，更新大型对话 Compose 状态；布局测量和高度动画同时参与，存在输入累计与动画竞争路径。尚无设备 Perfetto/frame-time 数据，不能把视频采样当成 CPU/GPU 性能测量。

按最终要求移除拖动回调、偏好高度及对应无极调节组件。新 handle 是 48dp 可访问点击区域，按下有弹簧反馈，展开沿用已有玻璃 morph。加载胶囊→收听圆窗→回复卡的弹簧过渡、真实音量波形及语音会话边缘发光保留。右上角两个按钮均移除；上方仅显示问题、声波和状态。

## 数据、上下文与安全

- 人格保存在本机；名称限制 32 字、描述限制 2000 字。人格描述只影响表达，不能覆盖事实来源、工具授权和确认流程。
- 沿用消息表现有 TEXT 分区键 `sessionDate`：旧日期键原样有效，新独立会话键为 `yyyy-MM-dd#UUID`。日事实/缓存仍使用真实 ISO 日期；发送历史会话时以当前可信时钟重新读取事实，不使用旧日期作为“今天”。
- 会话标题/空会话记录放在独立本机偏好中；消息正文仍由 Room 持久保存。发送时捕获会话键，成功回复与确认保存收据回到该键。
- 不再按两天删除用户消息。两天过期只用于可重新生成的日事实缓存；无引用附件清理保留。
- 回复期间使用共享互斥保护消息修改；创建保存未结束时也阻止历史修改。取消请求会将用户消息标为失败，保留协程取消语义。
- 编辑消息不自动重发、不修改任务；只保存正文，移除原操作草稿和运行痕迹，保留图片引用。删除先确认，删除聊天记录不删除课程或待办。
- 分组与搜索在后台线程执行，搜索等待 150ms 合并输入，列表按最近消息排序并使用 LazyColumn。
- 继续对话使用已有主页面全屏助理与确认链路；需要时切换到该对话所属课表，不把旧课表的事实或计划带入另一课表。
- BackupFormatV1 增加可缺省人格与会话元数据字段；旧备份默认人格和空元数据。恢复前校验格式、会话键及课表引用，标题按 stable schedule id 重映射；消息键沿用原导出/恢复路径。没有新增数据库字段或迁移。

## 设备验收步骤

1. 浮窗回复卡顶部没有全屏、关闭、麦克风按钮；点击底部短条进入全屏；全屏点击页面底部白色短条收起。返回、点击外部按预期工作。
2. 开启语音：三点加载→收听圆窗→处理→回复卡；唯一语音按钮在输入区。继续说话、输入文字、打断、暂停、鉴权失败、返回后台再恢复均无重复入口或残留发光。
3. 人格设置选三种风格并重启，编辑名称与描述；分别用文字和语音提问。创建请求只拟稿，确认前零写入。
4. 新建两个同日对话，分别发送内容；搜索、重命名、打开继续聊，检查上下文不串。跨天打开历史时“明天”应按当前日期解析。
5. 编辑/删除单条消息不影响已经创建的待办；删除整段对话需要确认。回复/保存过程中修改记录会被明确阻止。
6. 导出 `.shixu` 再恢复，检查旧消息、独立会话、名称与人格；导入旧备份不丢数据。
7. 窄屏、大字体、键盘、深浅壁纸、全屏往返检查布局、按钮与动画。
