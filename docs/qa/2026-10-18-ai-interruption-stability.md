# AI 语音中断稳定性：修复与验收记录

## 范围和证据

用户确认触发方式为「语音说话打断或停止自动朗读」。本轮先检查工作树及当前代码，再分配语音生命周期、Chat/Responses 取消和数据链路审查；主代理审查补丁并统一验证。DeepSeek V4.1 Flash 和 GLM 5.3 Flash 的委派被当前代理封装拒绝，实际执行的子代理使用 GPT-6 Luna，不能记作前两者完成了工作。

没有取得该用户手机当次崩溃堆栈。本轮发现的是能够由源码和定向测试确认的生命周期与取消缺陷，不能把它们直接等同于手机闪退的唯一根因，也不能声称全应用不存在其他 Bug。

## 实际修改

- `VoiceAudio`：先取消录音协程并用 `stop()` 唤醒阻塞读取，等读取任务退出后才释放录音器和回声消除器；重新开启前等待独立的硬件清理完成标记。仅等待读取任务 `join()` 不足以保证 completion handler 已释放硬件，新测试覆盖这一竞态。播放继续使用独立代际 token，旧数据不能写入新播放。
- `VoiceSession`：系统 TTS 的停止/销毁失败不再逃出清理路径。初始化、排队朗读和播放完成回调检查会话、引擎实例及轮次；旧回调不推进新轮次。初始化和完成后重启识别的普通异常转为可恢复的朗读失败，保留协程取消语义。
- `VoicePreviewPlayer`：旧试听的失焦及播放失败回调不再停止新试听。
- `DayAgentChatTransport`、`AgentOpenAiResponses`、`DayAgentService`：Chat 和 Responses 的 HTTP 连接绑定当前请求 Job，取消时断连，关闭异常不逃出取消处理器；读取、流式回调和格式修复边界检查取消。用户停止后不因取消异常继续格式修复请求，已取消回复不再继续写入助手历史。
- `AgentCreationDispatch`、`AgentCreationReceiptLedger`：修复混合创建计划中前批成功、后批失败后重新确认会重复创建前批的问题。同一进程中重试跳过已校验成功的批次；重复回调只消费一次，纯课程/待办单批保留原事务和撤销结果。
- 创建成功朗读由最终结果统一触发，避免分批执行时提前或多次播报完成。

创建检查点仍是进程内回执，沿用 128 个已完成回执的保留边界；进程终止、回执淘汰或数据库提交与回执登记之间中断后的跨存储幂等性不在本轮解决范围，不能宣称跨进程 exactly-once。本轮没有修改 Room、备份格式或数据库写入协议。

## 验证记录

首轮四个定向套件 17 项测试通过。最终冻结源码的 15 个定向套件共 91 项通过（0 失败、0 错误）。覆盖取消不进入修复、取消触发 HTTP 断连、关闭异常处理、阻塞读取所有者退出和硬件释放完成标记、批次重试与并发重复回调、最终完成播报、原事务/撤销结果、语音协议和响应跟踪、待办创建确认、模型发现解析。

新增两个原生测试：`AiInterruptLifecycleTest` 覆盖 40 轮前台服务启停顺序；`VoiceAudioInterruptTest` 使用合成静音 PCM，覆盖 30 轮录音、播放、中断、释放、重开和旧 token 隔离。这些次数是测试设计，**不是已执行成功次数**。

模拟器尝试仅针对 `emulator-5562`，未操作 USB 手机，未重启 ADB 服务或清除 AVD 数据。API 36 WHPX 进程启动后处于 Suspended；核实为本轮启动的精确 PID 和 SDK 路径后恢复，进程在 Android 完成启动前退出。API 26 缓存模拟器使用软件加速同样在启动阶段退出；再关闭 GPU/Vulkan 的定向尝试返回 `-1073741819`（`0xC0000005`），测试进程已退出。因此尚未安装本轮 APK 或执行上述原生测试，没有本轮手机复现、云端真实语音、TTS 服务中断或音频焦点切换验收结论。

构建使用实际可用的 `D:/Android/Android Studio/jbr`、工作区 Gradle 缓存及本机 SDK，单 worker、4GB JVM 堆、离线依赖。首次定向任务缺少 `ANDROID_HOME`，配置后通过；一次组合命令的 `--tests` 位置错误已改正。整合时主源码和新测试版本交错导致一次编译失败，随后统一重建；审查发现硬件清理完成标记竞态后，主动停止本轮 Gradle 客户端、补丁完成再冻结源码重跑。这些中间结果均不作为交付验收依据。最终 14 个源码/测试文件哈希在构建前冻结，交付时复核。
