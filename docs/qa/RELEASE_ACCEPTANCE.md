# 课表+ 发布验收清单

本文用于候选版本的端到端与设备验收。每次候选发布填写设备、系统、应用版本、日期和结果；未实际执行的项目保持“未验收”，不要以编译通过代替设备结果。

## 设备与数据准备

记录 API 26 手机、当前目标 API 手机和平板的型号、系统版本、屏幕尺寸与应用版本。准备一份 v42 课程数据、一份旧包名 `.sleepdown` 备份和一份含待办、分组、父子任务、课程关联的 BackupFormatV1 备份。测试前复制备份，不在唯一真实用户数据上进行恢复或清理。

## 待办完整流程

- [ ] 从列表创建任务，编辑标题、描述、截止日期、时间和优先级；关闭后重开，确认字段保留。
- [ ] 创建分组和子任务，完成父任务/子任务；删除分组后确认任务按既定规则保留，删除父任务后确认子任务按外键规则处理。
- [ ] 置顶、取消置顶、完成、撤销完成、删除和撤销入口符合 UI 提示；列表与洞察同步更新。
- [ ] 设置每日、每周、每月重复规则；完成后出现下一次任务。跨夏令时切换时本地时间不偏移；无截止日期任务不生成重复项。
- [ ] 从课程详情创建关联待办；课程详情、今日时间轴、待办详情与备份恢复都保留课程关联。

## AI 提取与系统分享

- [ ] 从应用内粘贴文本提取待办，预览后确认写入；取消预览不创建任务。
- [ ] 从相册选择单图与多图提取；分别测试无文字、损坏图片、超限文件和模型失败，错误应可理解且原始内容不丢失。
- [ ] 从其他应用分享 `text/*`、单张 `image/*` 和多图到课表+；冷启动和应用已打开时均进入相同预览流程。
- [ ] 关闭网络、使用无效 API URL/Key、文本模型或多模态模型，确认失败可重试且不生成半成品任务。
- [ ] 快速设置磁贴在未安装/未授权 Shizuku 时给出明确说明；授权后只在用户触发时读取屏幕，不持续采集。

## 日历、提醒与导航

- [ ] 月视图与周视图切换、日期选择和待办标记点正确；同日多任务标记可见且不遮挡日期。
- [ ] 手动同步两次、编辑任务后同步、删除任务后同步；系统日历中不产生重复事件，已同步事件按既定策略更新或移除。
- [ ] 开启自动同步后创建、编辑、完成和删除待办；与手动同步交错操作仍保持幂等。
- [ ] 首次拒绝日历权限、之后授予，再撤回权限；应用显示可恢复提示，不崩溃、不丢本地任务。
- [ ] 课程提醒和待办提醒发生在相邻时间时检查通知去重；点击通知直接打开对应课程或待办，完成/删除后旧通知不再打开失效项目。
- [ ] 通知权限拒绝后再授予；检查已排程提醒是否按产品规则恢复且没有重复通知。

## 时间轴、洞察与桌面组件

- [ ] 今日助手按本地时间顺序混排课程和待办；无时间、全天任务、时间冲突和跨午夜场景都有可读展示。
- [ ] 完成/取消完成任务后，完成率、压力分布和趋势图更新；空数据、单日数据与大量任务均可浏览。
- [ ] 添加、缩放和删除桌面课程/待办组件；跨日、换课表、编辑课程/待办后组件刷新；不同 host 尺寸无裁切。
- [ ] 撒花动画在减少动态效果或低性能设备下仍可完成状态更新；提示音开关即时生效，静音后不播放。

## 壁纸、布局与可访问性

- [ ] 首次安装无内置壁纸，默认纯白；整个产品只显示一个“选择壁纸”入口。
- [ ] 通过该入口选择静态图片、实况图和视频；视频静音播放，离开页面、切换到后台或关闭预览后停止，返回时按生命周期恢复。
- [ ] 无效/被撤销授权的媒体文件不阻断课程、待办与备份恢复；更换或清除媒体后玻璃层没有黑屏、旧帧残留或持续播放。
- [ ] 手机和平板分别检查浅色、深色、壁纸背景和纯白背景；系统字体放大后标题、按钮、日期、玻璃 Dock 和底部面板仍可读、可操作。
- [ ] 检查页面转场、卡片展开/收起、勾选动效与返回手势；快速连续切换无叠层残留。

## 迁移、备份与更新

- [ ] 使用 MigrationTestHelper 从 Room 42 升到当前 schema；课程数据保留，分组外键设为 NULL、子任务级联行为符合 schema。
- [ ] 从旧 applicationId 导出的 `.sleepdown` 导入；课程、学期、时间设置恢复，错误条目不阻断其他数据。
- [ ] BackupFormatV1 导出后清单含待办、分组、子任务和课程关联；calendarEventId、API Key 与密钥不写入备份。
- [ ] 恢复时日历事件映射重新建立或保持未同步状态；缺失壁纸资源只显示空背景，其他数据继续恢复。
- [ ] 更新器默认检查正式版；Beta 开关关闭时忽略 prerelease，开启后只显示匹配的 prerelease。
- [ ] 离线、无 Release、缺少更新 JSON、错误版本、错误 applicationId、外部主机 URL、无效 SHA-256 都显示可理解的失败信息。
- [ ] 使用包名/版本不匹配 APK 与内容被修改的 APK 验证拒绝；签名不匹配由 Android 安装器拒绝，正常包仍要求用户确认，不静默安装。
- [ ] 安装 Release 后检查包名、versionName/versionCode、签名连续性和更新后用户数据；回退安装旧签名/旧版本不得覆盖用户数据。
