# 开关触控、待办响应与按钮对齐排查

日期：2026-09-29  
版本基线：1.2.8 / versionCode 35  
分支：`codex/calendar-sync-orphan-recovery`

## 已由代码确认的问题与修复

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| 开关轨道点了没反应，像是要按住拖动 | 共用 `LiquidToggle` 把手势只挂在窄滑块上，轨道两端没有触控处理；触摸采样稍有横向抖动也会被当成拖动。 | 手势改挂在完整开关触控区，普通按下松开即可切换；只有越过触控阈值且以横向为主时才拖动。纵向滚动不会误切换，系统取消手势会恢复原值。添加 Switch 无障碍状态和点击动作，触控高度至少 48dp。 |
| 开关状态显得迟钝或没有正确落位 | 落位条件比较的是拖动状态，而本地 fraction 已经先被设成目标值；手势回调还可能持有过期的 `onSelect` 闭包。拖动输入则逐采样取消并重启弹簧。 | 用最新选中状态和回调，按动画当前位置触发落位弹簧；拖动目标按显示帧合并更新，限制每帧一次重定向。 |
| 完成待办后动画、提示音延迟 | 本地 Room 更新前先等待系统 Calendar Provider 删除事件；提供方响应慢会延迟任务完成显示和完成反馈。 | 先提交本地完成状态并立即触发完成反馈，再在 IO 上清理系统日历事件并更新提醒/组件。日历失败仍会走原有待重试清理链路。 |
| 截图中的筛选/优先级文字和图标不居中 | 待办按钮复用 `GlassSurface` 时，内部容器默认从左上排布；图标和短标签在固定尺寸胶囊中没有居中容器。 | 待办筛选/优先级选项设最小 64×48dp 并居中文本；图标按钮在 48dp 玻璃容器中央绘制。 |
| 完成勾选容易点空 | 视觉勾选圆圈只有 26dp。 | 保持 26dp 外观，点击和无障碍区域扩展到 48dp。 |
| 设置开关点击区域小于视觉规范 | 设置 Miuix 行为开关预留高度 28dp；禁用项只传空回调，没有传禁用状态。 | 预留区调整到 48dp，统一向开关组件传真实 enabled 状态。 |

待办列表中的“显示已完成”“完成提示音”，待办编辑中的“置顶”，日历中的“自动同步”现在都可以点轨道/滑块或对应文字切换，不要求长按。设置页及其它使用同一 `LiquidControlToggle` 的模块共享全轨道点击和触控阈值修复。

## 其他模块按钮巡查

- 共享 `GlassPill` 和 `LiquidButton` 的常规点击链路仍会挂载 Compose `clickable`；静态检查未发现一个持续覆盖所有页面的透明拦截层。
- 课程菜单、详情转场和截图遮罩确实会在打开/关闭动画期间暂时拦截触摸，设计上只在对应转场覆盖期间挂载，并在完成回调中清理。
- 没有连接的 Android 设备，也没有具体的其他模块、按钮和复现步骤；无法确认其它单独控件是否存在设备/窗口相关的命中区域问题。本轮修复了已确认的全局开关路径和截图中的待办控件，不能把静态检查替代为全模块实机验收。
