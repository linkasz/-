# AI 助理确认创建与语音浮窗交互验收

## 范围与依据

本轮在当前工作树上实现已确认计划，保留此前修改、壁纸自适应、自动朗读偏好和多平台配置。未改应用身份、版本、数据库或备份格式，未安装、推送或发布。

个人 Wiki 搜索“时序清单 AI 助理”没有结果，本报告依据本地源码、截图描述、构建与测试。ADB 设备列表为空；没有 AndroidRuntime 崩溃栈，因此下面的音频修复是已定位的代码风险处理，偶发闪退根因仍未确认。

已定位问题：

- 浮窗只呈现回复正文，确认操作主要在完整对话中渲染，创建草稿在浮窗中无法直接确认。
- 底部手势采用固定展开/关闭行为，没有共享的连续高度状态。
- 发光绘制有“已有回复或全屏”的限制，初始聆听浮窗不满足条件。
- 操作提取依赖 JSON 边界，事实对象与操作数组混合时可能取错；校验失败统一返回泛化提示。
- 输出片段在完整校验前进入界面，可信时钟、事实缓存和协议提示可能短暂显示或污染后续上下文。
- AudioTrack 的创建曾在播放异常边界外；播放完成、权限返回及连接回调缺少完整的过期会话约束。

## 实现与关键 diff

### 自然回复与确认

`AgentReplyBoundary.kt`、`DayAgentModels.kt`、`AgentTools.kt`：

- 平衡扫描 JSON，尊重字符串中的括号；跳过前面的事实对象，识别真正的操作数组。
- 保留字段校验结果，空数组作为正常无操作答复；不接受不完整或重复的操作标记。
- 传输片段先进入私有缓冲，完整正文和计划校验后才发布。内部时钟、事实缓存和工具协议不进入聊天/朗读。
- 创建类正文由校验后的草稿生成，例如“已拟好明天 10:00的「开会」待办，请确认。”
- “下午十点”先询问上午 10 点还是晚上 22 点；不在这一步调用模型或创建任务。
- Chat Completions 与 Responses 均最多进行一次格式修复，修复请求不带工具，复用已取得的事实；原有空响应/旧哨兵继续沿既有工具循环恢复。
- 后续请求过滤助理内部回显，用户消息保持完整，不删除数据库历史。

`AgentCreationProposal.kt`、`AgentCreationDispatch.kt`、`AgentCreationReceiptLedger.kt`、`DayAgentUi.kt`：

```diff
- 浮窗仅展示正文，操作确认需要进入完整对话
+ 浮窗和完整对话共用编辑、取消、确认创建卡片
+ 编辑返回重新校验的草稿，取消只改变界面状态
+ 确认后才领取执行回执，并调用原有保存链路
+ 相同草稿在保存中/已成功时拒绝再次执行
+ 重复保存回调只接收一次；保存失败可重试
+ 保存成功写入自然回复，并尊重自动朗读开关
```

`ScheduleAppUi.kt`、`ScheduleViewModel.kt`：确认后的待办、课程和课表保存使用应用生命周期，避免浮窗或页面关闭取消已确认的保存。待办继续在事务内保存并回读核对，课程继续调用现有仓库事务；提醒、组件及外部日历后续失败与本地创建结果分开说明。

### 连续高度与语音

`AssistantResizeHandle.kt`、`DayAgentUi.kt`、`ReferenceVoiceCrown.kt`：

```diff
- 底部上划关闭/固定档位
+ 48dp 手柄连续更新共享高度，正常松手不吸附
+ 仅越界时限制并回弹，键盘和窗口变化重新限制有效高度
+ 全屏使用独立按钮，往返保留高度
- 聆听立即显示旧圆窗，初始浮窗没有边缘发光
+ 蓝/紫/青三点加载至少可见 240ms，音频事件不延迟
+ 宽、高、圆角和内容使用同一弹簧过渡到收听圆窗
+ 所有活跃语音阶段持续绘制顺时针彩色边缘
+ 停止、失败、关闭或后台暂停时关闭绘制和资源
```

波形沿用已有开源参考实现并读取真实 PCM/RMS；等待动画独立于音量，不用循环波形冒充语音。保留上部约 2/3 磨砂、下部液态的渐变材质和低版本降级。浮窗内容可滚动，输入区与调整高度手柄位于底部。

`VoiceAudio.kt`、`VoiceSession.kt`：

- AudioTrack 初始化、缓冲/设备状态和播放都在异常边界内；保留协程取消。
- 录音、连接、权限及播放完成受会话/播放标识约束，迟到结果不能关闭新播放队列。
- 权限在后台返回时延后到前台开始录音；销毁后的回调不重新开启语音。
- 后台释放资源并保留恢复意图；前台重新连接、重新呈现加载。手动停止不恢复。
- 系统朗读期间停止识别，忽略非聆听阶段的旧识别回调，避免识别自己的声音。
- 诊断仅记录会话、阶段、错误类型及 traceId，不记录密钥、录音或完整聊天。

### 公共样式

`AppGlassIconButton.kt`、`SleepDownDesignTokens.kt`、`SleepDownQuickSheet.kt`：共享主色、图标、触控尺寸、边框、按压和禁用状态；全屏右上角收起按钮使用 42dp 玻璃圆按钮、22dp 图标和至少 48dp 默认触控区域。顶栏公共按钮和 QuickSheet 操作使用同一入口，保留各页业务行为与既有布局配置。助手继续按壁纸明暗使用黑/白玻璃底。

## 实机验收步骤及未验收项

1. 发送“帮我新建一个待办事项。我明天下午十点要开会。”应先澄清时间；选择上午十点后检查明天日期和 10:00 草稿，没有工具/时钟/JSON 回显。发送“生成完整计划”也不能泄露内部提示。
2. 在浮窗编辑名称和时间，切换全屏再返回；取消后列表不新增。重新提出创建，连续点击确认，列表仅新增一条，卡片和聊天回复显示已创建。待办、课程、课表分别执行此流程。
3. 确认保存后立即收起/关闭面板，再次进入检查回执。模拟保存失败及提醒/外部日历权限拒绝，失败说明与本地保存结果应分别显示，不重复创建。
4. 用手指、鼠标、触控笔拖动底部手柄，在非固定高度松手；检查内容滚动、键盘、横竖屏、安全区及全屏往返。触边仅发生限制/回弹。
5. 开启语音：加载三点至少可见 240ms，准备好后弹簧变形为收听圆窗。说话/静音分别观察真实音量波形；连接、查询和朗读期间发光持续顺时针流动，全屏往返不重置。
6. 拒绝/撤回麦克风权限、断网、打断、手动停止、后台再回前台、连续进入退出。自动朗读关闭时仅显示文字；开启时检查读出用户正文及创建成功回复，不读协议。
7. 深浅壁纸、视频壁纸、API26 降级及大字体检查文字和按钮。用真实设备帧统计核对性能；未测得 60fps，不作帧率或像素级复刻承诺。
8. 连接 vivo S50 / iQOO Z9 后采集 `adb logcat -b crash -d`，记录系统版本、会话阶段和触发步骤；有 AndroidRuntime 栈后再确认偶发闪退根因。

本轮 ADB 无设备，以上实机项目、真实百炼/硅基流动等服务调用、Android 音频资源释放与外观仍标为**未验收**。没有使用用户密钥进行云端请求。
